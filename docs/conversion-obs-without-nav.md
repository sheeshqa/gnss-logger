# Явная публикация OBS без NAV

По умолчанию конвертер требует полную запрошенную пару OBS/NAV.
Для коротких сегментов можно явно разрешить сохранение проверенного OBS,
если convbin не создал запрошенный NAV:

```powershell
python -m gnss_logger convert --config conversion.local.toml --input segment.ubx --allow-obs-without-nav
```

Эквивалентная опция TOML (по умолчанию false):

```toml
[output]
obs = true
nav = true
allow_obs_without_nav = true
```

CLI-флаг и настройка требуют одновременно включённых OBS и NAV.
Существующий OBS-only режим `obs=true, nav=false` не изменён: в нём NAV
вообще не запрашивается, это другая семантика.

## Условия и статус

- UBX должен пройти существующие проверки, включая fingerprint и целостность.
- convbin должен завершиться без timeout и с returncode=0.
- OBS должен пройти все существующие проверки.
- Запрошенный NAV должен именно отсутствовать. Пустой, повреждённый,
  нечитаемый NAV или неполное покрытие систем не включают этот fallback.
- Символические ссылки на выходе по-прежнему запрещены.

Статус сегмента и операции с такими сегментами:
`OBS_ONLY_INCOMPLETE_NAVIGATION`, exit_code=3.
Это намеренно **не SUCCESS и не SUCCESS_WITH_WARNINGS**.
При наличии других ошибок они не подавляются.

В отчёте/receipt:

- `published_outputs`, `outputs`, `output_fingerprints` содержат только OBS;
- `requested_outputs` сохраняет исходно запрошенные OBS и NAV;
- `missing_outputs=["nav"]` явно указывает отсутствующий продукт;
- warnings содержит `NAV missing: validated OBS published without navigation; conversion is incomplete`;
- `validation.obs` и исходный fingerprint сохранены;
- receipt публикуется атомарно штатным механизмом, с тем же неполным статусом.

В identity receipt добавляется `allow_obs_without_nav=true` только при
включённом режиме. Частичный receipt не переиспользуется строгой операцией
как полный успех. Проверенный повтор внутри той же операции сохраняет
неполный статус; новая операция получает новый каталог как прежде.

Существующие JSON schema_version сохранены; добавлены опциональные поля и
значение статуса. Потребители закрытого списка статусов должны учитывать его.
Фоновый worker уже учитывает возвращённые статусы и пути отчётов; код записи
не изменяется. При использовании worker режим включается в TOML явно.

## Научные ограничения

Структурно валидный OBS с флагом clock_reset может быть сохранён, но это не
разрешение непрерывно склеивать его фазу с соседними дугами. Для TEC/ROTI
нужны отдельные правила фазовой непрерывности и отбраковки.
Самостоятельный NAV короткого фрагмента может не сформироваться; использование
NAV соседних сегментов требует проверки временного покрытия эфемерид.

Поддержка сигналов и профиль RINEX 3.02 не расширены. Предупреждения
C6I/E6B/E6X и неподдерживаемых сигналов BeiDou сохраняются.
