## Вывод о реализуемости

Для ZED-F9P задача технически реализуема: [datasheet ZED-F9P-01B, UBX-17051259](https://content.u-blox.com/sites/default/files/documents/ZED-F9P-01B_DataSheet_UBX-17051259.pdf)
подтверждает raw code/carrier phase, Doppler и метрики качества. Наличие этих возможностей
не гарантирует, что нужные сообщения включены на выбранном порту.
[Release note HPG 1.51](https://content.u-blox.com/sites/default/files/documents/ZED-F9P-FW100HPG151_RN_UBXDOC-963802114-13110.pdf)
описывает RAWX/SFRBX и набор L1/L2-сигналов этой FW. Для другой аппаратной модификации
и прошивки диапазоны и ограничения надо сверить отдельно. Двухчастотный TEC требует
реально наблюдаемых валидных кодовых и фазовых измерений на паре частот одного спутника,
подходящей антенны и проверки downstream-конвертации.

Пример оценки UART, не измерение: 80 записей измерений дают 2584 байта RAWX-кадра.
При 1 Гц это 223257600 байт/сутки только RAWX. UART 115200, 8N1 имеет теоретический
предел 11520 байт/с; RAWX 10 Гц с таким числом измерений уже превосходит его без учёта
SFRBX/NMEA/RTCM. Предпочтение USB или иной скорости нужно согласовать с платой;
CLI скорость приёмника не меняет.

## Конвертация: исследована, но не проверена

[Официальный исходный код RTKLIB, ветка rtklib_2.4.3](https://github.com/tomojitakasu/RTKLIB/blob/rtklib_2.4.3/src/rcv/ublox.c)
содержит декодеры RAWX/SFRBX; [сайт RTKLIB](https://www.rtklib.com/)
описывает поддержку RINEX. Это основание для выбора convbin кандидатом,
но не доказательство сохранения всех сигналов конкретным exe.
[Официальная страница ошибок](https://rtklib.com/rtklib_support.htm) перечисляет, в частности,
проблемы Galileo NAV. Нельзя выбирать сборку только по названию RTKLIB.

До интеграции нужны exe, точная версия/commit, SHA-256, текст лицензии из выбранной сборки,
параметры и тестовый лог. Нужно сравнить OBS/NAV с RTKCONV на том же входе:
эпохи, диапазоны времени, C/L/D/S, спутники, частоты, эфемериды. Пока exe не установлен,
конвертация не запускалась и версия RINEX не зафиксирована. Для X20P требуется отдельная
матрица сигналов и проверка, без молчаливого отбрасывания неизвестных наблюдений.

## Google Drive: будущий этап

Использовать Desktop OAuth client, системный браузер, loopback redirect и PKCE согласно
[официальному OAuth guide](https://developers.google.com/identity/protocols/oauth2/native-app).
Scope выбирать минимальный; `drive.file` проверять относительно способа выбора существующей папки.
Refresh token хранить через защищённое хранилище Windows, вне репозитория и отчётов.
Состояние приложения OAuth (Testing/Production), срок refresh token и тип аккаунта проверить
перед автономной многосуточной эксплуатацией.
[Drive upload guide](https://developers.google.com/workspace/drive/api/guides/manage-uploads)
описывает resumable upload, опрос принятого диапазона и восстановление после сетевых ошибок.
Очередь должна сохранять session URI локально как чувствительные данные; завершение проверять
по ответу API и метаданным, а не по факту начала запроса. Реализация и авторизация пока не выполнялись.

## До первого подключения — обязательные ответы

1. Какая ОС и разрядность на рабочем компьютере, какая версия Python? Windows 10 из документа ещё актуальна?
2. Полная маркировка ZED-F9P (суффикс), модель платы/адаптера и схема подключения?
3. USB самого приёмника или USB-UART, какой COM, драйвер и текущий baud/8N1? Есть ли другой владелец порта?
4. Есть ли известные FWVER/PROTVER или старый MON-VER? Если нет, допустим ли одиночный MON-VER poll?
5. Соединены ли RTS/DTR с RESET, BOOT, питанием или другими управляющими входами?
   Каковы уровни UART и стабильность питания? Не подключать UART напрямую к RS-232.
6. Тип и диапазоны антенны, активная ли она, её питание, кабель, разъёмы и место установки?
7. Уже включены ли RAWX/SFRBX на выбранном интерфейсе? Есть ли сохранённый короткий UBX-лог?
8. Частота для диагностики: 1 Гц или иная? Какие системы и пары частот нужны для исследования?

Эти ответы нужны до оборудования; отсутствие FW можно разрешить документированным запросом чтения.
Если сообщения отключены, данная версия CLI их не включит. Изменение конфигурации будет отдельной задачей
со снимком и явным подтверждением.
