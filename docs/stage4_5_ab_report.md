## Реализация

### История

[HistoryCoordinator](../gnss_logger/gui/history_coordinator.py) использует существующий
`HistoryService`, без новой базы данных, хеширования UBX и исправления архивов.
Сканируется только явно заданный набор roots. Один worker и один заменяемый pending
запрос ограничивают очередь; generation token не допускает устаревшей доставки.

[Страница истории](../gnss_logger/gui/pages/history.py) разделяет результаты записи,
сохранённую оценку целостности и результаты конвертации. Сохранённая целостность
не является новой проверкой. Неизвестные метрики показываются как «Нет данных».
Пути открываются через Qt desktop services, без shell-команд; удаления нет.

### Preferences и TOML

[preferences.py](../gnss_logger/gui/preferences.py) хранит GUI-only defaults, roots
истории и состояние интерфейса в versioned JSON. CLI от этого файла не зависит.
Чтение не создаёт и не перезаписывает файлов. Повреждённый файл сохраняется;
явное восстановление сначала создаёт эксклюзивную резервную копию исходных байтов.

[toml_writer.py](../gnss_logger/gui/toml_writer.py) сериализует только существующую
схему `ConversionSettings`. Это не альтернативный TOML-парсер: загрузка и проверка
выполняются штатным loader. Дополнительных зависимостей нет. Неизвестные поля
отклоняются; комментарии и форматирование не сохраняются, поэтому перезапись
требует явного подтверждения. Save As сохраняет смысл путей, записывая абсолютные
значения. Перед публикацией временного TOML проверяется round-trip Settings.

Оба хранилища используют эксклюзивный sibling `.lock`, SHA-256 revision,
`fsync` временного файла и атомарную замену. При конфликте требуется reload;
автоматического retry и снятия старых lock нет. Это кооперативная защита
участвующих экземпляров, не блокировка произвольных внешних редакторов.

## Ручная проверка без оборудования

Из корня репозитория, в PowerShell:

```powershell
$mock = Join-Path $env:TEMP 'GNSS-GUI-MOCK\stage45-manual'
& C:\Users\user\AppData\Local\GNSS\.venv-gui\Scripts\python.exe -m gnss_logger.gui --mock --mock-root $mock
```

1. В «Настройках» изменить станцию и продолжительность, нажать «Сохранить».
   Проверить показанный путь файла настроек: он должен находиться внутри mock root.
2. На странице конвертации изменить поддерживаемый параметр, «Сохранить как…»
   в TOML внутри mock root. Сохранить путь профиля по умолчанию в настройках.
3. Закрыть окно, повторить ту же команду. Проверить восстановление станции,
   продолжительности, TOML, раздела и положения окна. Идентификация приёмника
   не должна восстанавливаться как подтверждённая; запись сама не запускается.
4. Через mock-команды создать синтетическую запись/конвертацию. В «Истории»
   обновить список, проверить поиск, фильтры, отдельные статусы, подробности,
   копирование пути и открытие существующего файла/каталога. Перезапустить окно
   с тем же root и убедиться, что история сохранилась.
5. Изменить TOML в форме, закрыть окно: проверить «Отмена», затем отказ от
   сохранения или явное сохранение. При перезаписи TOML должно появиться
   предупреждение о потере комментариев/форматирования.
6. Во время mock-записи изменить defaults: активная операция должна сохранить
   исходные параметры. Отдельные Auto On/Off и Cancel сохраняют прежний смысл.

В обычном режиме файл GUI defaults располагается в
`%LOCALAPPDATA%/GNSS/config/gui-preferences.json`; conversion TOML остаётся отдельным.
Mock CLI принимает root только ниже `%TEMP%/GNSS-GUI-MOCK`, не корень этого каталога.
Временные mock-каталоги могут очищаться Windows: это не хранилище настоящих измерений.

### Найденные при проверке интеграционные дефекты

- Defaults baud применялся к coordinator, но не к полю записи: теперь обновляются оба.
- Чрезмерные координаты/размеры JSON могли переполнить Qt integer или создать
  недоступное окно: восстановление ограничено доступной геометрией экрана.
- Числа, не представимые формой GUI, не должны молча обрезаться spinbox:
  при загрузке сохраняется исходный файл и показывается предупреждение.
- Длительность в секундах округлялась при переводе в минуты с тремя знаками:
  воспроизведено 95 → 94.98 и 95.123 → 95.1. Добавлена единица «Секунды»,
  значение передаётся напрямую; 95 / 95.123 / 0.001 / 60000000 проходят регрессию.
  Алгоритм записи не менялся. Формы поддерживают три десятичных знака:
  более точные значения defaults отклоняются с предупреждением, не округляются молча.
- Первый общий прогон выявил UTF-8 BOM в новом Python-файле (сбой ast.parse
  проверки синтаксиса 3.9) и WinError 32 при удалении test report, пока новый
  history worker ещё читал его. BOM удалён, teardown ждёт все четыре контроллера.
  Это отдельная установленная причина, не исправление ранее известной
  нестабильности cancellation/cleanup и не изменение тестов диагностики.
- Следующий общий прогон выявил гонку readiness в старом helper Stage 4.4:
  он ждал только первоначальный TOML loader, но не новый preferences loader;
  запрос второй операции мог отклоняться как busy и проверяться прежнее значение.
  Helper теперь ждёт оба владельца перед действиями. Проверки результата TOML
  не изменены; последовательно повторяется весь GUI-модуль.

## Контрольная точка

Реализация 4.5a–b, native Windows smoke, снимки страниц и инструкция готовы.
Функциональные проверки новых возможностей PASS. Общая регрессия **PARTIAL**:
два известных диагностических FAIL и повторно наблюдавшийся intermittent cleanup.
Эти ограничения явно сохраняются при коммите, без заявления о полном PASS.

### Ограничения и следующий этап

- Большие архивы: дорогой metadata scan, синхронная публикация таблицы;
  времена измерены выше. Это не обещание мгновенной истории на 1000 сессий.
- Defaults сохраняются явно. После первого сохранения preferences закрытие
  обновляет размещение окна/раздел; без первого сохранения новый файл при закрытии
  не создаётся. Несохранённые текущие параметры записи не становятся defaults.
- Roots, использованные текущими операциями, добавляются к обновлению истории
  в памяти. Для доступности нестандартного архива после перезапуска его root нужно
  явно добавить и сохранить в настройках истории.
- Stage 2 передаётся к ручной конвертации по run_id, только если в текущей истории
  он однозначен. Для неоднозначных попыток и многофайлового Stage 1 требуется
  ручной выбор источника; GUI не выбирает случайную попытку.
- Хранилища рассчитаны на кооперативных писателей; stale lock не снимается
  автоматически. Конфликт требует reload, неизвестные TOML поля не удаляются.
- Нет аппаратной приёмки GUI, проверки всех DPI/нескольких физических дисплеев,
  EXE/portable/installer, лицензионной приёмки поставки.

Следующее согласование — приёмка 4.5a–b. Затем отдельные 4.5c (оформление,
статусная строка, доступность, руководство) и 4.5d (проверка происхождения/лицензий,
EXE, portable, installer). Stage 4.6 не запускался. Полный Stage 4.5 не объявляется
завершённым только на основании этой контрольной точки.
