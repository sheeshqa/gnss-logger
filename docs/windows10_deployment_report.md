## 1. Git и публикация

В действующем домашнем проекте Git отсутствует: rev-parse/status/remote вернули
not a git repository. Новый .git там не создавался. Коммитов, remotes, создания GitHub repo,
push и передачи GNSS-данных не было. Решение о Private repo, аккаунте, доступе и публикации
оставлено пользователю. Временный Git только в отдельном проверочном каталоге без remotes.
Расположенный в OneDrive исходный проект не перемещался.

## 3. Проверки

Создана отдельная копия из файлов, разрешённых .gitignore. Она не содержит реального
data, reports, аппаратных артефактов, личных конфигов или готовой домашней venv.
Новая venv создана с нуля; в ней успешно выполнены pip install -e . и pip check.
Установлены gnss-logger 0.4.0.dev1 и pyserial 3.5, сборка setuptools — изолированная.

Полный тестовый прогон в переносимой копии:

```text
Ran 111 tests in 1.179s
OK (skipped=1)
```

110 тестов успешны, один skip — необязательный большой пользовательский UBX, намеренно
не включённый в перенос. Это ожидаемое отличие от домашнего прогона 111/111 с реальным логом.
F9P/X20P/полночь проверяются тремя явно синтетическими fixtures. Ровно эти UBX и sidecar
разрешены точечными исключениями; реальных наблюдений среди них нет.

Проверены работа установленного пакета из другого cwd с Python -I и console entrypoint
gnss-logger.exe --version: 0.4.0.dev1; импорт идёт из новой переносимой копии.
Копия использует собственную venv и не импортирует исходники из домашнего проекта.
pyproject.toml не содержит путевых зависимостей; runtime gnss_logger/ и tools/ не содержат
домашних user/OneDrive путей. C:/record в контрактных тестах — фиктивная строка schema,
не реальный файл; необязательный data/... тест пропускается, если его нет.

PowerShell parser проверил все 9 блоков инструкции: синтаксических ошибок нет.
Аппаратные команды из документа только разобраны как текст, не выполнены.
Это не выполнение под Windows PowerShell 5.1 на рабочем ноутбуке: его среда проверяется отдельно.

Ignore проверен по разрешённым исходникам/schema/templates/fixtures и запрещённым
UBX/RINEX/секретам/конфигурациям/аппаратным файлам. Локальный поиск известных форматов
GitHub PAT/private keys в кандидате переноса совпадений не обнаружил; это не доказательство
отсутствия любых возможных секретов. Перед первым commit/push требуется ручной просмотр staged diff.

Данные и аппаратные артефакты проверены по сохранённым SHA-256/размерам: все 68 защищённых
файлов неизменны, как и исключённые личная конфигурация и hardware reports.
Реальные UBX/RINEX не редактировались, не удалялись и не перемещались.

Среда выполнения проверки: Windows 11, Python 3.12.14 x64. Работа на Windows 10 и выбранной
там patch-версии Python должна быть подтверждена пользователем, не выводится из этого теста.
Официальные ссылки на Python/Git/GitHub и особенности получения Python 3.12 указаны в инструкции.

## 4. Действия пользователя

1. Подтвердить состав переноса и разрешить публикацию; выбрать GitHub аккаунт/Private repo.
2. После подтверждения создать пустой Private repo, проверить staged файлы и отправить код.
3. На рабочем ноутбуке установить Python 3.12 x64 и Git for Windows, войти через GCM.
4. Клонировать вне OneDrive; создать соседние data/config/deployment вне Git-клона.
5. Создать новую venv, установить -e ., выполнить pip check и автономные тесты.
6. Выполнить ручной read-only smoke: ports → inspect 30 с → passive 120 с → Replay/хеши.
7. Передать версии, commit ID, вывод тестов и весь отдельный каталог smoke для анализа.

Обновления: завершить регистрацию, git status, git pull --ff-only, pip install -e .,
тесты; не применять git clean/reset --hard и не обновлять работающий процесс. Данные
сохраняются в соседнем каталоге, поэтому не входят в область Git update.

**Публикация ожидает отдельного подтверждения.** Автоматическая многосуточная запись,
reconnect, RINEX/TEC/Drive/GUI не добавлялись.
