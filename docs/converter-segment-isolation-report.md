# Отчёт: пропуск control-only сегментов и изоляция конвертации

Дата: 2026-11-17. GNSS Logger 0.5.0.dev2, Windows, Python 3.15.1.

## Изменения

- [cli.py](../gnss_logger/conversion/cli.py): отдельный каталог
  `conversion-<operation_id>` в настроенном корне или под `--output`;
  агрегация с учётом `SKIPPED`; дополнительные каталоги для одноимённых
  сегментов внутри одной операции.
- [engine.py](../gnss_logger/conversion/engine.py): пропуск проверенного
  undated-сегмента без RAWX; отложенная проверка интерфейса convbin;
  пропущенный сегмент не скрывает разрыв между соседними OBS-сегментами.
- [test_stage31_conversion.py](../tests/test_stage31_conversion.py): обновлены
  проверки структуры каталогов и повторных операций; добавлены проверки
  пропусков, повреждений, fingerprint, реальной ошибки subprocess,
  предупреждений, параллельных операций и одноимённых сегментов.

Запись UBX, последовательный порт, диагностика, фазовые измерения,
конфигурация оборудования и профиль RINEX не изменялись. Аппаратные тесты
не выполнялись. Существующие изменения пользователя в декодере и диагностике
сохранены без вмешательства.

## Правила статусов

| Статус | Условие |
| --- | --- |
| SKIPPED сегмента | После проверки целостности `rawx_epochs == 0` и `Source.utc_day is None`; причина `skip_reason=no_rawx_undated_control_only` |
| SKIPPED операции | Все выбранные сегменты пропущены; exit code 0 означает отсутствие ошибки, но не создание RINEX |
| SUCCESS | Все непропущенные сегменты успешны, нет предупреждений или предупреждений границ |
| SUCCESS_WITH_WARNINGS | Все непропущенные сегменты успешны, есть предупреждения сигналов, качества/непрерывности или границ |
| FAILED | Сохраняются реальные ошибки источника, convbin, проверки OBS или публикации; пропуск другого сегмента их не нейтрализует |
| INCOMPLETE_NAVIGATION | Сохраняется существующая классификация неполной/невалидной NAV; SKIPPED ей не мешает |
| CONFLICT | Сохраняется защита от реальных коллизий/повреждённых receipts внутри выбранного каталога |
| ALREADY_CONVERTED | Сохраняется низкоуровневая проверка verified receipt и fingerprint внутри каталога; новая операция по умолчанию конвертирует заново |

`PARTIAL` не является статусом этой подсистемы; новый статус PARTIAL не введён.
Существующие `DRY_RUN`, `INTERRUPTED`, `NOT_RUN` сохранены. Dry-run по-прежнему
показывает команды и проверяет интерфейс convbin без создания файлов;
решение SKIPPED относится к обычному выполнению с анализом содержимого.

Отсутствие *пригодных измерений* при наличии RAWX не равно отсутствию RAWX:
такой источник по-прежнему ошибочен для OBS. Датированный сегмент без RAWX
также сохраняет прежнее поведение: ошибка при запросе OBS, возможность NAV-only.
Датой считается существующее поле `Source.utc_day` из метаданных сегмента;
для явного `--input` это поле отсутствует. Дата не угадывается из имени файла
или времени Windows; существующая политика датирования записи не меняется.

До пропуска проверяются fingerprint, непрозрачные байты, незавершённый хвост,
ошибки декодирования и неизменность источника. Пропуск не запускает convbin,
включая help/version probes, и не публикует OBS/NAV или receipt успешной
конвертации. Источник, fingerprint, статус и причина остаются в отчёте операции.

## Совместимость и размещение

Параметры CLI сохранены. Преднамеренное изменение: `--output` и output.root
теперь задают родительский каталог операций, а не непосредственное место OBS.
Для потребителей доступны существующие абсолютные пути `report_path`,
`published_outputs`, `result_path`, а также новое поле `output_directory`.
Добавлено поле сегмента `skip_reason`; версии JSON-схем не изменены.
Потребители закрытого перечня статусов должны учесть SKIPPED.

Пример двух операций над одним UBX:

```text
<output.root>/
  conversion-<operation-A>/
    X20P_20261116.obs
    X20P_20261116.nav
    X20P_20261116.conversion.json
    conversion-<operation-A>.json
  conversion-<operation-B>/
    X20P_20261116.obs
    X20P_20261116.nav
    X20P_20261116.conversion.json
    conversion-<operation-B>.json
```

Одноимённые сегменты одной операции размещаются в `segment-<index>/`.
Существующий отчёт операции служит сводкой; per-segment receipt остаётся
commit marker. Новая система manifest/storage не добавлялась. Manifest записи
не меняется и остаётся связан через run_id/attempt_id/artifact_id источника.
Фоновый worker уже вызывает execute отдельно для каждого сегмента: каждый
такой вызов теперь имеет свой каталог и отчёт, а существующая recording-сводка
продолжает учитывать результаты этих операций.

## Проверки

Команды выполнены из корня проекта интерпретатором
`C:/Users/user/AppData/Local/GNSS/.venv/Scripts/python.exe`:

```text
-m unittest discover -s tests -p test_stage31_conversion.py -q
-m unittest discover -s tests -q
```

- Связанные тесты: 34, успешно 34, ошибок/неуспешных 0, пропущено 0.
- Полный набор: 216, успешно 213, неуспешных 2, пропущен 1.
- Пропуск: отсутствует необязательная сохранённая запись COM4 для offline-теста.
- Два сбоя находятся в ранее изменённом пользователем
  [test_diagnostics.py](../tests/test_diagnostics.py), вне конвертера:
  `test_all_chunk_boundaries_and_mixed_stream` ожидает discarded_bytes=0,
  получает 14; `test_sfrbx_length_mismatch_is_not_counted` ожидает ключ без
  префикса, получает `02-13: Invalid SFRBX word count or payload length`.
- Проверка редактора изменённых Python-файлов: ошибок нет.
- `git diff --check`: успешно.

Тесты используют существующие синтетические UBX/RINEX и subprocess fixture.
Изоляция проверена последовательно, параллельно и для одинаковых имён
сегментов. Сохранены проверки реального CONFLICT при гонке публикации,
rollback при ошибке receipt и верификации существующих результатов.
Предупреждения C6I/E6B/E6X и BeiDou проверены без изменения таблицы сигналов.

## Ограничения

Два сбоя диагностики отдельно зарегистрированы и воспроизведены с исходным
конвертером: [известные проблемы диагностики](./known-diagnostics-issues.md).

Фактический RTKLIB на аппаратной записи повторно не запускался: эта работа
проверена автономными автоматическими тестами. Новые каталоги увеличивают
потребление диска при повторной конвертации; автоматическая очистка не добавлена.
Полный набор тестов не зелёный из-за двух указанных диагностических сбоев;
изменять эти модули в рамках данной задачи запрещено.
