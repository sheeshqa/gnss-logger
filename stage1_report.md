# GNSS Logger — Stage 1, автономная часть

Дата: 2026-10-21. Версия: 0.2.0.

**Результат: автономная часть Stage 1 завершена. 51/51 тест прошёл.**
Физические COM-порты в этой итерации не открывались. Serial Mode и оба устройства:
**NOT TESTED на оборудовании**. GUI не создавался.

## 1. Реализованные функции

- Три режима CLI: `serial` (старое имя `diagnose` также работает), `replay`, `mock`.
  Все байты поступают в общий `engine.run_source` и `Diagnostics`.
- Serial: явный выбор COM/baud; пассивный режим по умолчанию; понятная ошибка открытия,
  занятого/недоступного порта и отсутствие аварийного traceback. Программа возвращает
  диагностический код ошибки, а Replay/Mock продолжают быть доступны без устройства.
- Независимые `F9PAdapter` и `X20PAdapter`: обнаружение по MOD в MON-VER, отдельные карты
  проверенного поднабора ключей. Для X20P использованы официальные определения HPG 2.02.
  Это read-only поддержка интерфейса, не подтверждённая аппаратная совместимость всех FW.
- Необязательные MON-VER и `--inspect`: чтение RAM `RATE-MEAS`, `RAWX-USB`, `SFRBX-USB`.
  Список разрешённых пакетов проверяется до Serial.write. VALSET/VALDEL/RESET и произвольная
  отправка заблокированы. Метод применения профиля вызывает PermissionError.
- Один ожидаемый запрос, тайм-аут, проверка соответствия ответов. ACK не подменяет данные;
  NAK и отсутствие ответа явно отражаются в отчёте. Запросы в сохранённом UBX только разбираются,
  никогда не отправляются на устройство.
- Replay: `--speed 0` без задержек, `--speed 1` по времени эпох, `--speed N` ускоренно.
  Кодовые/фазовые измерения не прореживаются, пропуски не заполняются. Между RAWX-пакетами
  исходные сообщения сохраняют порядок, но их отдельные исходные времена доставки неизвестны.
- Mock: F9P/X20P, MON-VER/VALGET, normal/partial/timeout/nak/ack/ack-only/corrupt/malformed/no-data.
  Виртуальные часы ускоряют тесты тайм-аутов. FWVER `MOCK-F9P`/`MOCK-X20P`, PROTVER `MOCK`,
  `simulated=true` и sidecar отделяют фикстуры от измерений. Синтетический NAV содержит только
  пакетную структуру, не рабочие эфемериды.
- Формирование UBX, checksum, потоковый разбор частичных/повреждённых пакетов, RAWX v1,
  SFRBX v2, MON-VER, VALGET v0/v1, ACK/NAK. Неизвестные версии диагностируются.
- Бинарная запись без изменения байтов; SHA-256; новые имена без перезаписи; flush/fsync,
  корректное закрытие при конце источника, ошибке или Ctrl+C.
- `--record-dir`: прототип сегментов по UTC. Replay использует RAWX week/TOW/leapS при
  валидном leapS либо явный `--start-utc`. Serial использует UTC времени чтения на компьютере.
  До первого известного времени Replay требует явный UTC-якорь для записи.
- Диагностика интервалов и разрывов: начало/конец и длительность пробела, оценка пропущенных
  эпох; исходные данные остаются неизменными. Список подробных пробелов ограничен 1000,
  остальные учитываются счётчиком. C/N0, валидность code/phase, half-cycle и locktime сохраняются
  в статистике; исходные поля полностью остаются в UBX.
- Исходные данные станции сохранены в `config/station.example.json`; неизвестные поля — null,
  высоты не преобразуются в предполагаемый datum. Принятые ответы: `docs/user-context.md`.

## 2. Результаты автономных тестов

Команда: `.\.venv\Scripts\python.exe -m unittest discover -s tests -v`.
**51 тест, 7.819 с, OK, ошибок/пропусков нет.**
Полный фактический вывод: [autonomous_tests.txt](docs/evidence/autonomous_tests.txt).

Покрыты checksum/сборка и неверные заголовки, все разрезы пакета по чанкам, ресинхронизация,
разбор числовых значений, версии, некорректные VALGET/ACK, оба адаптера, все mock-сценарии,
корреляция и тайм-ауты, запрет write, ошибка и отсутствие COM через заглушки, отсутствие данных,
битовая сохранность, ошибка диска, полночь UTC, повторный запуск, обратный ход даты, остановка
и закрытие файлов. Проверка 30-секундного интервала не меняет поток и не вставляет эпохи.

Фактически использован `.venv` Python **3.12.14**. Editable-install 0.2.0, CLI entry point
и `pip check` проверены. Для Python 3.9 выполнена проверка синтаксиса, но не runtime-тест.
Заявленные пользователем Windows 11/Python 3.13.14 и целевые Windows 10/Python 3.9.13
не выдаются за проверенную матрицу; перенос/автономный exe требуют отдельных испытаний.

## 5. Известные ограничения

- Serial не переподключается автоматически: завершает текущий короткий сеанс с ошибкой;
  автоматический reconnect и восстановление сессии — Stage 2. Безопасность линии RTS/DTR
  на реальной плате не подтверждена; намеренного переключения в программе нет.
- UTC-ротация Serial основана на времени чтения компьютера, может отражать буферизацию USB
  и разрезать UBX-пакет. Научное распределение эпох по суткам и границы после потери времени
  требуют доработки Stage 2. В Replay целый RAWX относится к своей вычисленной UTC-дате,
  остальные байты — к последней известной эпохе; это не гарантия полноты суточных NAV.
- RAWX time примерно согласован с GPS; leapS/clock reset не заменяют независимую поверку UTC.
  Replay с неизвестным временем требует явного `--start-utc` для записи. Эффекты leap second
  и изменения корректировки времени в длительном сеансе ещё не покрыты аппаратно.
- Нет контроля места/устойчивой БД/расписания/защиты от сна/восстановления после сбоя питания.
  Flush/fsync каждые 5 с и в конце не являются гарантией сохранности при сбое ОС.
- Декодируются RAWX v1/SFRBX v2; потолок payload фреймера 16384 байта. Повреждённая длина
  может задержать восстановление до накопления байтов. Сырые байты сохраняются, без маскировки ошибок.
- Адаптеры читают только общий независимо сверенный USB/RAM-поднабор. Полная матрица FW,
  конфигурация остальных интерфейсов/сигналов и серийный ID не реализованы.
  Архивный официальный Interface Description HPG 1.13 пока не получен; это отмечено в protocol.md.
- Нет convbin/RINEX, проверки LLI/эфемерид/gnss_tec, Google Drive OAuth/очереди и GUI.
  Пользовательская сборка demo5 b34k ещё не проверялась. Фазовые данные не исправляются.
- Provenance сообщает известное происхождение, не криптографическую подлинность произвольного UBX.
  Файл без synthetic-marker/sidecar считается непроверенными сохранёнными байтами, а не новым
  аппаратным измерением. Локальные исходники не удаляются автоматически.
- Windows 10/Python 3.9.13, Windows 11/Python 3.13.14 и автономная сборка — NOT TESTED отдельно.

## 6. Условия перехода к Stage 2

Автономный допуск Stage 1 выполнен: общий pipeline работает, 51 тест зелёный, Replay проверен
на пользовательском файле и синтетических фикстурах, mock-ответы/ошибки воспроизводимы,
отсутствие приёмника обработано, аппаратные проверки вынесены отдельно.

Можно продолжать независимую разработку Stage 2 без устройства: устойчивая БД/manifest,
reconnect с новым сегментом, disk guard, schedule и recovery, управляемые часы и длительные
синтетические прогоны. Не выдавать это за аппаратный допуск.

До реального запуска подтвердить разъём/ревизию и антенну, получить актуальный MON-VER,
прочитать конфигурацию, записать 10–30 минут, проверить отключение/возврат USB и сравнить файл.
Для эксплуатационного допуска далее требуется длительный 48–72-часовой тест отдельно F9P/X20P,
проверка целевой ОС/runtime и последующая валидация RINEX 3.02 на текущем TEC/ROTI-ноутбуке.
GUI остаётся отложенным до успешного аппаратного тестирования CLI.
